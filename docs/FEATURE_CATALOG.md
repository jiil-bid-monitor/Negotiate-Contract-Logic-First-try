# 기능 목록 — 다른 수집기와 비교·이식용 (2026-10-16 기준)

세부 판정 규칙(정규식·기준값·처리 순서, 싱크로율 계산식 포함)은 짝 문서 `docs/LOGIC_DETAILS.md`에 있다.

이 문서는 **팀원 수집기(다른 저장소)와 기능을 비교하고, 이 저장소에만 있는 기능을 옮겨 심을 때** 쓰는 자료다.
각 기능에 ID(F-01…)를 붙였다. 기능마다 "무엇을 하나 / 규칙 / 겪은 함정 / 코드·설정·테스트 위치"를 적었다.
코드 원본: `kdh-007/Negotiate-Contract-Logic-First-try` main 브랜치. 결정 배경은 루트 `CLAUDE.md`(날짜별 메모).

## 0. 팀원 저장소 쪽 Claude에게 줄 지시문 (그대로 붙여 넣기)

> 이 저장소(팀원 수집기)와 `kdh-007/Negotiate-Contract-Logic-First-try`의 `docs/FEATURE_CATALOG.md`를 비교해 줘.
> (세부 규칙은 같은 폴더 `docs/LOGIC_DETAILS.md` — 규칙 차이를 볼 땐 그 문서 기준으로)
> 1) 카탈로그의 기능 ID마다 우리 저장소에 **있음 / 일부 있음 / 없음**을 표로 정리하고, 있으면 우리 쪽 파일 위치와 규칙 차이를 적어 줘.
> 2) 같은 기능인데 규칙이 다른 곳(예: "또는" 판정, 마감 우선순위)은 어느 쪽이 맞는지 판단하지 말고 차이만 나열해 줘.
> 3) "없음" 기능은 아래 의존 관계와 이식 순서를 보고 옮길 순서를 제안해 줘. 코드는 내가 승인하기 전엔 고치지 마.
> 4) 이식할 때는 원본 저장소의 테스트(카탈로그에 적힌 `tests/…`)도 같이 옮겨 우리 구조에 맞게 고쳐 줘.

비교가 끝나면 그 결과표를 이 문서와 같이 보고 결정하면 된다.

## 2. 기능 상세

### F-01 나라장터 API 클라이언트 — `nego/http_client.py`
- 오류가 `{"nkoneps.com.response.ResponseError": …}`처럼 오면 응답 트리를 재귀로 뒤져 `resultCode`를 찾음(고정 경로면 99로 덮임).
- items가 배열 / 객체 하나 / `{item:[…]}` / `{item:{…}}` / 빈 문자열 5가지로 옴 → 한 모양으로 정규화.
- `type=json`을 보내도 인증 오류는 XML로 옴 → 둘 다 파싱.
- 오류 문구·로그에서 서비스키를 가림(`mask_service_key`) — 요청 URL이 예외 메시지에 그대로 들어가는 문제.
- 기간 30일 초과는 나눠서 조회(`chunk_date_range`).
- 테스트: `tests/test_http_client.py`.

### F-02 응답 칸 이름 후보 — `nego/fields.py`
- 같은 의미의 칸이 업무(용역·물품·공사)·서비스마다 이름이 다름 → `FIELD_CANDIDATES`에 후보를 나열하고 앞에서부터 고름(`pick`).
- **실측으로 고친 것**: 물품 본공고의 세부품명번호는 `dtilPrdctClsfcNo`(이름 `dtilPrdctClsfcNoNm`, 여러 품목 `purchsObjPrdctList` "[1^번호^이름],…"),
  사전규격 물품은 `prdctDtlList`. `prdctClsfcNo`만 보면 **물품 품명코드 매칭이 한 번도 안 됨**(10/14 발견).
- 담당자 이름·전화·메일 칸 제거(`strip_personal_fields`).

### F-03 수집 범위 — `nego/scope.py`
- 순서가 중요: **최신 차수를 먼저 고르고 → 취소 여부**. 반대로 하면 "000 등록 → 001 취소"에서 000이 살아남음.
- 수의계약 제외: 계약체결방법(`cntrctCnclsMthdNm`)에 "수의" 포함(실응답으로 확인).
- 유형: 협상(낙찰방법 `sucsfbidMthdNm`이 "협상에의한계약"으로 시작) / 규격가격동시입찰 / 입찰(그 밖 전부).
- 테스트: `tests/test_pipeline.py`.

### F-04 사전규격 — `pipeline.collect_prespecs`
- 서비스 주소 `…/1230000/ao/HrcspSsstndrdInfoService`(활용신청 별도). 본공고와 같은 키워드·예산 필터.
- 마감 = 의견등록 마감(`opninRgstClseDt`). 면허제한·공동수급 정보 없음 → 자격은 첨부로만.
- `bidNtceNoList`가 있으면(이미 본공고로 나감) 후보에서 빼고 "본공고 게시됨"으로 기록.
- 사전규격 첨부는 파일명 칸이 없어 내용(매직바이트)으로 형식 판별.
- 응답에 상세 주소 칸이 없음 → 링크는 `https://www.g2b.go.kr/link/PRVA004_02/single/?bfSpecRegNo=<등록번호>`로 만듦.
- 사전규격 조회가 실패해도 본공고는 계속.
- 테스트: `tests/test_prespec.py`.

### F-05 날짜 단위 조회 — `complete_days_window`
- 매일 보고는 "어제 하루", 매주 보고는 "지난 7일"을 **날짜 경계(00:00~23:59)로 잘라** 조회 → 발송 기록 없이 같은 공고를 두 번 안 보냄.
- 워크플로에 `TZ: Asia/Seoul` 필수(러너가 UTC면 하루 밀림).
- 테스트: `tests/test_schedule_window.py`.

### F-06 키워드·예산 필터 — `nego/screen.py`, `config/keywords.json`
- 비교 대상 = 공고명 + 대표 품목명, **띄어쓰기 무시**.
- `keywords`(관심 18개), `excludeKeywords`(조건부 72개), `hardExcludeKeywords`(무조건: 특별전·순회전),
  `excludeKeywordExceptions`({"건축": ["실내건축"]} — "실내건축"은 "건축"으로 안 침),
  최소 예산 없음(2026-10-27 회의 결정 — 예전 `minBudgetAmount` 1억·설계 용역 예외 삭제).
- `keywordSkipWhen`(특정 낱말이 있으면 그 관심 키워드를 무시) 기능은 남아 있으나 설정은 비어 있음.
- keywords.json 안 `_…comment` 칸에 키워드마다 넣고 뺀 이유가 적혀 있음 — 이식할 때 같이 옮기면 판단 근거가 보존됨.

### F-07 품명코드 매칭
- 대표 품명 + 품목 목록 전부(`Notice.product_codes`) 중 하나라도 `codes.json`에 있으면 일치.
- 업종만 일치하는 공고는 후보가 아님(업종 단독 매칭 금지).

### F-08 검토 필요 — `ScreenConfig.review_conflicts`
- 공고명에 제외 키워드가 있어도 관심 키워드가 함께 있으면 버리지 않고 `confidence="검토필요"`로 따로 모음(웹앱만 켬, CLI·텔레그램은 기존대로 제외).
- 계기: 완도 체험관 "전시연출 설계 및 제작·설치" 15억이 "연출"로 빠짐.

### F-09 보유 면허 0개 제외 — `qualify.no_held_license`
- 면허제한 API의 모든 그룹·행에서 지일 보유 면허(대표 또는 허용업종)가 하나도 없으면 제외 — 공동수급(분담이행)도 불가라서.
- 하나라도 있으면 남기고 "자격 미달"로만 표시. 사전규격·첨부에만 적힌 자격엔 적용 안 함.

### F-10 지역제한 — `nego/region.py`
- 회사 소재지 `held_qualifications.json` `companyRegion`(강원특별자치도 정선군)과 시·도 단위 비교 → 충족/미달/미확인.
- 근거: 첨부 참가자격 문장(소재지·주된 영업소·본점·본사·관내 + 시도명)이 API 참가가능지역보다 우선(`combine`).
- "공동수급·구성원·권장·우대·가점" 문장은 제한으로 안 봄(오탐 방지). 지역의무공동도급도 제한 아님.
- **미달이면 제외**(10/14 결정 — 지역제한은 공동수급 구성원 모두가 요건을 채워야 함). 그래서 첨부를 읽은 **뒤에** 거름.
- 테스트: `tests/test_region.py`.

### F-11 면허제한 API 해석 — `nego/qualify.py`
- **제한그룹끼리 "또는", 그룹 안 행끼리 "모두 필요", 행의 허용업종 = 대신 인정**(실측: 백령 체험관, 세종도서관 출판사/인쇄사, 폐기물 6조합).
- 면허제한 API는 `bidNtceNo`를 줘도 서버가 거르지 않음 → **기간 전체를 한 번 받아** 공고번호로 묶음.
- 정정공고 차수마다 같은 행이 또 옴 → 공고별 **마지막 차수만**.
- 판정은 **코드 비교 + 이름 완전일치**(부분일치 금지 — "실내건축공사업"이 "건축공사업"을 충족하는 오류).
- 허용업종 코드도 남김(`split_industry_list` "이름/코드").

### F-12 첨부 텍스트 추출 — `nego/attachments.py`
- HWP(olefile, 컨트롤 문자 잡음 제거·글자겹치기 복원), HWPX(zip 안 XML), PDF(pypdf), ZIP(안의 문서를 이어 붙임,
  CP949 파일명 복원, zip 안 zip 한 겹, 공고·제안요청·과업지시 이름 먼저, 문서 60개·개당 80MB·총 300MB 제한).
- xlsx 등 지원 안 하는 형식, DRM 잠긴 파일(앞 64바이트에 DRM·SCDSA·FSD 등)은 **실패가 아니라 건너뜀**(`AttachmentUnsupported`).
- 개인 연락처(전화·메일) 제거(`redact_personal_contacts`).
- 테스트: `tests/test_attachments.py`, `tests/test_attachment_samples.py`.

### F-13 참가자격 절 찾기 — `nego/qualification_text.py`
- **목차를 잡는 버그가 흔함**(과거 제안요청서 87건 중 57건) → 본문 한글이 10자 이상인 첫 절을 고름.

### F-14 첨부 참가자격 코드 판정 — `qualify.evaluate_attachment_text`
- "또는/혹은"으로 이어진 코드끼리만 OR 묶음, 묶음 밖은 모두 필요. "어느 하나"는 항목 전체 OR. "[업종코드 A, B, C]" 나열(또는 없음)은 AND.
- OR로 보는 추가 형태: 닫는 괄호가 여러 겹(")]") 뒤 "또는", "업종 또는", "(허용업종코드 : 3243 또는 3276)",
  "코드 뒤 40자 안 서술이 업체/업자/자로 끝나고 또는", "신고/등록(한) 또는", "신고하거나".
- 이름표 복원: 줄바꿈에 잘린 이름을 앞 줄 조각과 이어 붙임, "따른/의한/의/로" 떼기, 이름 안 "A 또는 B"면 B.
- 대괄호 없는 "(1478)" 4자리는 코드로 안 봄(연도 오탐).
- 규칙을 바꿀 때마다 과거 문서 약 290건으로 전후 대조 — 판정이 바뀐 문서를 원문으로 확인.

## 4. 이식할 때 주의

- **두 수집기는 API 키만 다르고 자료(공고문·보유 자격·과거 실적 등)는 같음**(10/16 사용자 확인) — 비교는 **코드의 규칙·처리 방식** 위주로 하면 됨.
  설정 파일(`config/*.json`) 값이 다르면 그건 자료 차이가 아니라 판단(키워드 선택 등)의 차이이니 따로 표시할 것.
- **API 키가 다르면 활용신청 범위도 다를 수 있음** — 이 저장소가 쓰는 서비스: 입찰공고정보서비스(본공고·면허제한·참가가능지역·기초금액),
  사전규격정보서비스(F-04), 낙찰정보서비스(F-29 일부·F-30). 기능을 옮긴 뒤 "활용신청 안 됨" 오류가 나면 그 서비스를 신청하면 됨.
  `python -m nego --verify`(Actions `verify=true`)로 서비스별 응답을 한 번에 확인할 수 있음.
- **비밀값**: 나라장터 키·텔레그램 토큰·Supabase 키는 코드에 넣지 말고 Secrets/`.env`로. 로그에 키가 찍히지 않게(F-01 가림 처리).
- **개인정보·사내 자료**: 지일 투찰 이력 엑셀, 과거 실적(`jiil-past-contracts`)은 공개 저장소에 올리지 말 것.
- **보유 자격**: `config/held_qualifications.json`(10/14 만료 17개 정리, 26개)과 `codes.json`(15개)이 최신 — 팀원 쪽 목록과 대조할 것.
- **실측 우선**: 이 저장소의 많은 규칙은 실제 공고에서 틀린 걸 보고 고친 것(CLAUDE.md에 공고번호 있음). 규칙을 합칠 때 그 공고로 양쪽 결과를 비교하면 빠름.
- **환경**: Claude Code 웹 환경에선 나라장터·텔레그램 접속이 막힘 → 실제 호출 확인은 GitHub Actions 수동 실행 또는 사내 PC.
