## 1. 전체 처리 순서

`nego/pipeline.py run()` → (웹앱은 `webapp/collect.py _run_nego()`가 이 순서로 부름)

```
① 조회 기간 결정       period(직접 지정) > complete_days(날짜 단위, 어제/지난 7일) > lookback_days(최근 N일~지금)
② 본공고 수집          용역·물품·공사 3종. 하나라도 실패하면 ApiError(부분 데이터로 진행 안 함 → 재시도)
③ (선택) 사전규격 수집  실패해도 본공고는 계속(prespec_error)
④ 면허제한 API         기간 전체 1회 조회 → 공고번호별로 묶음. 실패하면 자격 판정 건너뜀(fail-open)
⑤ 참가가능지역 API      기간 전체 1회 조회 → 공고번호별
⑥ build_candidates     공고마다: 범위(scope) → 일정 → 키워드·예산(screen) → API 자격 판정 → 지역(API)
                       제외 순서: 본공고 게시된 사전규격 → screen 불일치 → 보유면허없음
⑦ (선택) 첨부 처리      후보만. 내려받기 → 텍스트 → 참가자격 절 → 첨부 마감 → 지역(첨부 우선) → 확인 필요 칩 → 코드/이름 판정 합치기
⑧ drop_region_unmet    지역 "미달" 후보를 제외로(첨부를 읽은 뒤여야 함)
⑨ 정렬                 (마감 남은 일수, 강력추천 먼저, 공고명)
⑩ 출력                 웹앱 JSON / 텔레그램 / HTML·CSV
```

**자격 미달은 제외하지 않는다**(공동수급 가능성 — 담당자가 판단). 제외하는 것은 ⑥의 보유면허 0개와 ⑧의 지역 미달뿐.

## 3. 수집 범위 — `nego/scope.py apply_scope`
순서 고정: **① 공고번호별 최신 차수만**(`latest_ordinals`) → **② 취소공고 제외** → **③ 수의계약 제외**(`cntrctCnclsMthdNm`에 "수의") →
④ 유형 분류 `bid_category`: 낙찰방법이 "협상에의한계약"으로 시작 → 협상 / 규격가격동시입찰 → 규격가격 / 나머지 → 입찰. 사전규격은 "사전규격".
⑤ 요청한 유형(categories)만 남김. 재공고 여부는 `is_re_notice`.

## 4. 키워드·예산 필터 — `nego/screen.py screen()`
비교 문자열: `_squash` = 공백 제거. 키워드 대상 = 공고명 + 대표 품목명. **제외 키워드는 공고명만** 봄.

판정 순서(위에서 걸리면 끝):
1. **무조건 제외**(`hardExcludeKeywords`: 특별전·순회전) → `제외키워드`
2. **조건부 제외**(`excludeKeywords` 72개). 단 `excludeKeywordExceptions`({"건축":["실내건축"]})에 적힌 낱말은 공고명에서 지운 뒤 검사.
   - 웹앱(`review_conflicts=True`)이고 관심 키워드도 있으면 → 제외 키워드 없이 3~5를 다시 돌려 통과하면 `confidence="검토필요"`, `review_exclude=제외어`
   - 아니면 `제외키워드`
3. **해외 전시회 한국관/단체관** → `해외개최` 제외. "한국관" 단독, 또는 (전시회|박람회|엑스포) + "단체관". **단 "몽골"이 있으면 제외하지 않고 `overseas_flag`**(확장 중인 시장).
4. **최소예산**: budget이 있고 1억 미만이면 `최소예산` 제외. 예산 정보 없으면 통과. 공고명에 `minBudgetExemptKeywords`("공사 설계 용역")가 있거나 "설계"와 "용역"이 다 있으면(`screen.is_design_service`, 10/19) 면제.
5. **매칭**: 품명코드(`product_codes` ∪ 대표번호 중 하나가 codes.json productCodes에 있음) 또는 관심 키워드. 업종(industryCodes 이름이 industry_text에 포함)은 **단독으론 후보 아님**. 셋 다 없으면 `미매칭`(몽골 예외).
6. 통과: `confidence` = (코드 일치 그리고 키워드 일치) → 강력추천, 아니면 참고용(화면에선 더 안 씀, 정렬에만).
- `keywordSkipWhen`(특정 낱말이 공고명에 있으면 그 관심 키워드 무시) 기능은 있으나 설정 비어 있음.

## 5. 면허제한 API 판정 — `nego/qualify.py`
1. **묶기**(`group_license_rows`): 행마다 공고번호·차수·제한그룹번호. 이름 = `lcnsLmtNm`("실내건축공사업/4990") + 허용업종목록(`[이름/코드][…]` → "이름/코드" 유지).
   공고별 **가장 큰 차수만**. 같은 그룹에서 대표 면허가 같은 행은 한 행으로 합침(허용업종 합집합).
2. **의미**: 그룹끼리 **또는**, 그룹 안 행끼리 **모두 필요**, 행 안(대표+허용업종)은 **또는**.
3. **보유 판정**(`_is_group_satisfied`): 이름 끝 코드(`/0002` 또는 `(0002)`)가 보유 코드에 있거나, 코드 뗀 이름(공백 제거)이 보유 이름과 **완전히 같음**. 부분일치 금지.
4. **보유 0개 제외**(`no_held_license`): 모든 그룹의 모든 행 중 보유로 채워지는 행이 하나도 없으면 제외 사유 "보유면허없음 (요구 면허 …)".
5. **요건 목록으로 펼치기**(`license_requirements`, 화면·판정 공용):
   - 그룹 1개 → 행마다 "필수"
   - 모든 그룹에 공통인 행(대표 면허 기준) → "필수"
   - 공통 행만으로 채워지는 그룹이 있으면 → 원문 그대로 "조합"(예: "1253 + 6728" 또는 "1253")
   - 나머지가 그룹마다 1행 → "택1"(N개 중 1개)
   - 나머지가 (A 또는 B) × (C 또는 D)의 모든 조합이면(`_factor_slots`) → 칸마다 "택1-N"(칸이 1개면 필수)
   - 그 밖 → "조합"(방법마다 행 목록)
6. `evaluate`: 요건마다 충족 여부 → `missing_groups`/`satisfied_groups`. `passes`는 계산만(후보 선정에 안 씀).

## 6. 첨부 처리 순서 — `nego/attachments.py save_attachment_texts`
후보마다, 첨부마다:
1. 내려받기 → 형식 판별(확장자, 없으면 매직바이트) → 텍스트. 지원 안 함·DRM → **건너뜀**(시도·실패로 안 셈). HWP/PDF를 못 읽으면 실패.
2. 텍스트를 `attachment_text`에 "=== 파일명 ===" 구분으로 이어 붙임. 개인 연락처 제거.
3. `find_qualification_section` → 항목들을 `all_items`에 모음(모든 첨부 합침).
4. `extract_deadlines` → 전부 `schedule.attachment_deadlines`에. 나라장터 자격등록·입찰·의견등록 마감이 모두 비었으면 그중 가장 이른 것을 카드 마감으로.
5. (첨부 다 읽은 뒤) 지역: `region.combine(API판정, from_text(all_items))` — 첨부가 미확인이 아니면 첨부 우선.
6. 확인 필요 칩: `flag_requirements(all_items)` + 출처 파일명.
7. 코드·이름 판정: 이름 사전(lookup) = code_names + 이번 실행에서 배운 이름 + 공고 대표 품명 + API 면허 이름 → `evaluate_attachment_text` → API 결과와 `merge_results`.

ZIP: 안의 HWP/HWPX/PDF/ZIP만 대상(공고·제안요청·과업지시·규격·시방 이름 먼저), 문서 60개·개당 80MB·총 300MB, zip 안 zip 1겹, CP949 파일명 복원.

## 7. 참가자격 절 찾기 — `nego/qualification_text.py find_qualification_section`
- 제목 정규식 `_HEADING_RE`: 줄머리 번호(`2.`, `3.1.`, `3)`, `나.`, `나)`, `Ⅱ.`, `□■◎◇◆▶●○`, `제N장/절/조`, 없음) + (입찰)참가자격(글자 사이 공백 허용 — "입 찰 참 가 자 격") + 꼬리(요건·조건·사항, "및 ○○") + 줄 끝까지 쪽번호·콜론 안내문만. **줄 전체가 제목이어야**("참가자격을 증명하는 서류"는 아님).
- 절 끝(`_SECTION_END`): 제목 번호 종류별 — `2.`→ 다음 `N. 글자`·로마숫자 / `3.1`→ 같은 급 소수·상위 / `나.`→ 다음 `다.`·상위 / `3)`→ `4)`·`다.`·상위 / 로마 → 로마 / □■◇◆ 기호 제목은 **같은 기호 줄**에서도 끝. 최대 4000자.
- 고르기: 우선순위 ① 번호+"입찰참가자격" ② 번호+"참가자격" ③ 번호 없음, 각 순위 안에서 **본문 한글 10자 이상인 첫 절**(목차 건너뛰기).
- 못 찾으면 `_find_item_block`: "가." 줄이 "시행령 제12조/제13조"를 인용하면 그 가나다 묶음(2항목 이상, "가."가 다시 나오면 끝)을 절로.
- 그래도 없으면 가장 긴 후보. 항목 나누기(`split_items`): 가./3.1./1)/o○/①② 순으로 2개 이상 잡히는 첫 패턴, 없으면 통째 1개.

## 8. 첨부 참가자격 코드 판정 — `qualify.evaluate_attachment_text`, `_or_groups`
**코드 추출**(`_locate_code_requirements`, 줄마다, 괄호가 열린 채 끝난 줄바꿈은 먼저 합침):
0. 괄호 안 맨 앞 키워드 + 코드 2개 이상: `[업종코드 4440, 4442, 4444]`
1. 키워드 바로 뒤 괄호: `업종코드(…)`, `세부품명번호 10자리(…)` — 4~10자리 전부
2. 키워드 뒤 코드 1개(`업종코드: 4990`, 자릿수 설명 건너뜀) 또는 정확히 10자리 단독 괄호 `(7215409901)`
3. 그 밖 괄호/대괄호 — **정확히 10자리만**(연도·조항 오탐 방지). 대괄호 없는 "(1478)" 4자리는 코드 아님.

**이름표**: 아직 닫히지 않은 괄호 안이면 안쪽, 아니면 괄호 앞 마지막 조각에서 연결어("에 따른/따라/의하여/의한/까지/포함한…")를 떼고
마지막 구절, "A 또는 B"면 B, 줄바꿈에 잘린 앞 조각(조사·어미·"자/함/업체" 아님, 1~4글자) 이어 붙임, 항목번호 떼기, 20자(+괄호 길이) 제한.
이름 우선순위: 등록증(held) > 코드 사전·API 이름 > 문서 이름표(서류명 "증명서·확인서·등록증" 등이면 버림) > 같은 공고 다른 곳 > "이름 미확인(코드)".

**또는/모두**(`_or_groups`): 코드를 위치순으로 놓고 이웃 사이 글자로 연결 판단
- 항목에 "어느 하나" → 항목 전체 OR
- `_OR_LINK_RE`(닫는 괄호 여러 겹·"업종" 허용 후) "또는/혹은" | "(허용업종" | 40자 안 서술이 "업체/업자/자/신고(한)/등록(한)"으로 끝나고 "또는" | "신고/등록하거나" → **or**
- 쉼표 → **comma**(뒤로 이어지는 연결이 결국 "또는"으로 끝나면 OR로 승격: "A, B 또는 C" = 셋 중 하나)
- 그 밖 → **and**("[업종코드 A, B, C]"처럼 "또는" 없는 나열은 모두 필요 — 사용자 확정)

**판정**: 묶음 안 하나라도 보유 → 묶음 충족, 묶음마다 미충족이면 요건 1건씩 `missing`. 보유로 채운 2개 이상 묶음은 "또는" 충족 요건으로 남김.
코드 없는 항목·하위 항목은 9장의 이름 판정. 충족 표시 목록은 절 원문 전체에서 보유 코드(독립된 4·10자리)를 훑어 만듦(표시용).

## 12. 싱크로율 — `webapp/sync.py` + `jiil-past-contracts/evaluation/task_profile.py`

**과업 프로필 만들기**(`build_profile(texts, title)`):
1. `task_scope`: `section_text.split_sections`로 절을 나눠 제목에 제안서·평가·협상·계약·입찰·참가자격·서식·붙임·별지·별첨·질의·문의·제출이 든 절을 도려냄
   (단 그 절이 원문 40% 넘으면 목차를 절로 잘못 잡은 것이라 안 도려냄). 남은 줄 중 배점·점수·평가 항목·제출 서류·보증·지체상금·기술자·하도급·보험·대금 등 행정 문구 줄 삭제. HWP 잡음 문자 제거.
2. 표준어 사전 `VOCAB`(9칸, 표준어 122개, 칸마다 정규식): 시설·주제(박물관·과학관·어린이체험·기념관·역사·생태·해양·놀이·경관·홍보관 등 31) / 과업유형(기본계획·설계·제작설치·구매·콘텐츠개발·디자인개발·운영) /
   공간범위(전시실·체험실·로비·벽체·천장·야외·수조·놀이공간 등) / 분야(건축·인테리어·구조·전기·통신·소방·기계·조명·음향·토목조경·방수·수처리) /
   콘텐츠·매체(영상·2D3D·4D·VR·AR·XR·실감·미디어파사드·홀로그램·인터랙티브·게임·AI·모형·조형물·그래픽·사인·놀이기구·가구·포토존·캐릭터·인쇄물·웹앱·해설·아카이브) /
   설비·장비(영상장비·음향장비·경관조명·제어시스템·키오스크·PC서버·CCTV·VR기기·RFID) / 철거·교체 / 운영·관리 / 일정·절차.
3. 줄마다 정규식 검사 → 걸린 줄 수가 `counts`, 첫 줄이 `evidence`(근거). **시설·주제**는 공고명에 나오거나 원문 **3줄 이상**일 때만(`SUBJECT_MIN_LINES`).
   공고명에만 있으면 근거 "(사업명) …".

**유사도**(`similarity`): 태그 무게 = **IDF × 칸 무게 × (1 + ln 등장 줄 수)**, 가중 코사인(0~1).
- IDF = ln((N+1)/(df+1)) + 1 (과거 실적 150건 기준, 과거에 없는 태그는 1.0)
- 칸 무게 `FACET_WEIGHT`: 시설·주제 1.6 · 콘텐츠·매체 1.5 · 설비·장비 1.3 · 공간범위 1.2 · 과업유형 1.0 · 분야 0.8 · 철거·교체 0.8 · 운영·관리 0.5 · 일정·절차 0.4

**점수**(`PastIndex.score(title, text)`):
- 입력 전처리: 첨부 구분 줄("=== … ===") 삭제, "나라장터" → "나라 조달시스템"('장터'가 전통시장 태그로 잡히는 오탐).

- 태그가 하나도 없으면 "판정 불가". 아니면 150건과 모두 비교해 **최고값 = 싱크로율**. 상위 5건 + 겹친 태그.

- "겹친 과업" 발췌(1위 실적과 겹친 태그의 근거 줄, 칸 무게 큰 순 → 이름순, 최대 4줄): 과업 동사(제작·설치·설계·시공·구축·조성·연출·전시·체험·콘텐츠·영상·미디어·조명·사인·VR/AR 등)가 있고,
  자격·조건 표현(입찰·참가자격·법령·체납·신용·확인서·제출·평가·배점·보증·공동수급·하도급·대가·하자·연락처·일시·마감·"위치/장소 :")과 학력·경력 표현이 없는 줄만.

## 15. 투찰 계산기 — `webapp/static/bidcalc.js`, `nego/bidcalc.py`
- 예비가격 = 기초금액 × (1 + 변동률%), 끝자리 올림(총액 1원 / 단가 0.01원 / 시설공사·감리·설계 100원), 서로 다른 15개, 번호에 무작위 배치.
- 변동률: 행자부(±3%) 15개·아래8/위7이면 기본서 표 15구간(0.00000001% 단위) / 조달청 15개면 기본서 표 15구간(±2%, 0.001% 단위) — 공고 범위가 표와 다르면 비율로 늘이고 줄임.
  난수추출 = 범위 안 균등, 등비추출 = 양 끝 사이 같은 비율. 표와 개수가 다르면 아래·위 개수만큼 칸 나눠 칸마다 1개.
- 예정가격 = 고른 4개(또는 3개) 산술평균. 투찰금액 = A + (예정가격 − A) × 낙찰하한율(A값 미적용 공고는 A=0).
  순공사원가 투찰가격 = 순공사원가 × (예정가격/기초금액) × 98%(추정). 끝자리 처리: 절상·절사·사사오입 × 원미만·10·100·1,000·10,000원.
- A값 = 국민연금·건강보험·노인장기요양·퇴직급여충당금·산업안전보건관리비·안전관리비·품질관리비(qltyMngcstAObjYn=Y일 때만). 방식 추정: 결정기준에 "지방" 또는 ±3% → 행자부.
