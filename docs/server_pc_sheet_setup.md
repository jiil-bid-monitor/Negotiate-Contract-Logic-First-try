# 서버 PC 설정 — 판단 기록을 피드백 구글 시트에 함께 쓰기

> 서버 PC(사내 웹앱 "나라장터 공고 수집"이 켜져 있는 PC) 담당자용 안내입니다. 한 번만 하면 됩니다. 15분 정도 걸립니다.

## 피드백 시트는 왜 필요한가

지금까지 판단 기록(참가·보류·불참)은 **서버 PC 안의 웹앱에만** 있었습니다. 그래서:

- 웹앱은 **사내망에서만** 열려서 외근·재택 중에는 누가 어떤 공고를 어떻게 판단했는지 볼 수 없었습니다.
- 서버 PC가 꺼져 있으면(담당자 휴무 등) 아무도 판단 기록을 볼 수 없었습니다.
- 보고된 공고 목록(시트)과 판단(웹앱)이 따로 있어서 두 곳을 오가며 맞춰 봐야 했습니다.

피드백 시트는 이걸 **구글 시트 하나로** 모읍니다.

| 시트 열 | 누가 채우나 | 언제 |
|---|---|---|
| A~R 공고 정보 (공고명·기관·금액·마감·링크 등) | GitHub 자동 보고 | 텔레그램 보고가 나갈 때마다 (서버 PC와 상관없음) |
| S~V 판단 (판단·사유·판단자·판단일) | 서버 PC 웹앱 | 웹앱에서 판단을 누르면 1분 안에 |

- **어디서나** 휴대폰·집 PC로 시트를 열어 "어떤 공고가 보고됐고, 누가 참가·불참으로 정했는지"를 한 번에 봅니다.
- **놓친 공고**가 바로 보입니다. 판단 없이 마감이 지나면 S열이 "놓침"으로 바뀝니다.
- 시트는 정렬·필터가 되니 기관별·금액별로 지난 판단을 돌아보기 쉽고, 나중에 관심 키워드나 제외 규칙을 고칠 때 근거가 됩니다.
- **서버 PC가 꺼진 날**에는 시트 S열 드롭다운에서 직접 판단을 적어 둘 수 있습니다. 웹앱이 다시 켜져도 지워지지 않습니다.
  다만 웹앱 판단 기록에는 안 들어가니, 켠 뒤 웹앱에서 한 번 더 눌러 주세요.

판단은 계속 **웹앱에서** 하고, 시트는 **보는 곳**입니다. 이 설정은 웹앱이 판단을 시트에 옮겨 쓸 수 있게 하는 작업입니다.

## 무엇이 바뀌나

웹앱에서 공고에 **참가·보류·불참**을 고르면, 1분 안에 팀 피드백 구글 시트의 같은 공고 줄 오른쪽 칸에 함께 적힙니다.
팀원은 웹앱에 들어가지 않아도 시트 하나로 "보고된 공고 + 누가 어떤 판단을 했는지"를 볼 수 있습니다.

| 시트 열 | 들어가는 값 |
|---|---|
| S 판단 | 참가 · 보류 · 불참 · 미판단 · 놓침 |
| T 사유 | 고른 사유 / 적은 메모 |
| U 판단자 | 고른 사람 이름 |
| V 판단일 | 고른 시각 (한국 시각) |

시트: https://docs.google.com/spreadsheets/d/1hUIsG95_0DRDyJYvlOC3rt4pJZ5gDREnRyOKXVDYf4o/edit

## 준비물

**구글 서비스 계정 키 파일 (JSON)**: GitHub 저장소 Secrets `GOOGLE_SERVICE_ACCOUNT_JSON`에 넣은 것과 같은 키입니다.
- 키 파일을 가진 분(시트 연동을 등록한 분)께 받습니다.
- 아무도 없으면 새로 받을 수 있습니다: 구글 클라우드 콘솔(https://console.cloud.google.com) → **IAM 및 관리자 → 서비스 계정** →
  시트에 편집자로 공유된 계정(`…@….iam.gserviceaccount.com`) → **키** 탭 → **키 추가 → 새 키 만들기 → JSON**.
  새로 받은 키는 GitHub Secrets에 있는 키와 따로 동작하니 Secrets는 바꾸지 않아도 됩니다.

> 이 키는 비밀번호와 같습니다. 메신저·메일로 돌리지 말고, USB나 직접 전달로 받으세요.

## 순서

### 1. 최신 코드 받기
웹앱이 켜져 있는 Git Bash 창에서 `Ctrl + C`로 끈 뒤:
```bash
git pull
```

### 2. 키 파일 두기
키 파일을 **레포 폴더 밖**에 둡니다. 레포 안에 두면 실수로 GitHub에 올라갈 수 있습니다.

예: `C:\Users\<윈도우 사용자 이름>\jiil-keys\feedback-sheet.json`
(폴더 `jiil-keys`를 만들고 받은 파일 이름을 `feedback-sheet.json`으로 바꿔 넣기)

### 3. `.env`에 두 줄 추가
레포 폴더 맨 위의 `.env` 파일을 메모장으로 열고 맨 아래에 붙입니다(경로는 2번에서 둔 곳으로, 역슬래시 `\` 대신 `/`).
```
FEEDBACK_SHEET_ID='1hUIsG95_0DRDyJYvlOC3rt4pJZ5gDREnRyOKXVDYf4o'
GOOGLE_SERVICE_ACCOUNT_FILE='C:/Users/<윈도우 사용자 이름>/jiil-keys/feedback-sheet.json'
```
저장하고 닫습니다.

### 4. 웹앱 다시 켜기
```bash
bash webapp/start.sh
```
서버 창에 이 줄이 보이면 성공입니다.
```
  피드백 시트에 판단 쓰기: 켜짐
```
1분쯤 뒤 서버 창에 `피드백 시트에 판단 N줄을 옮겨 썼습니다`가 나오고, 시트 S~V열이 채워집니다.
처음 한 번은 S~V 머리글이 "판정·오판사유·판정자·판정일" → "판단·사유·판단자·판단일"로 바뀝니다.

## 안 될 때

| 서버 창에 나온 것 | 해결 |
|---|---|
| `피드백 시트에 판단 쓰기: 꺼져 있음` | `.env`의 두 줄 이름·따옴표 확인 후 다시 켜기 |
| `서비스 계정 키 파일을 읽을 수 없습니다` | 3번 경로가 2번에 둔 파일 위치와 같은지 (`/` 사용, 파일 이름·확장자 `.json`) |
| `HTTP 403` … 편집자로 공유 | 시트 오른쪽 위 **공유**에 키 파일 안 `client_email` 주소가 **편집자**로 있는지 |
| `구글 액세스 토큰 발급 실패` | 키가 지워졌거나 잘못된 파일 — 준비물대로 새 키 받기 |
| 아무 줄도 안 바뀜 | 시트에 있는 공고(보고에 나간 공고)만 채웁니다. 웹앱에서만 본 공고의 판단은 시트에 안 들어감 — 정상 |

## 알아 둘 것

- **웹앱이 켜져 있어야** 시트에 반영됩니다. 꺼져 있던 동안의 판단은 켜면 1분 안에 따라 들어옵니다.
- 시트에 사람이 직접 적어 둔 판단은 지우지 않습니다. 웹앱에서 판단을 지우면 시트 칸도 비웁니다.
- 판단은 계속 **웹앱에서** 합니다. 시트에서 고친 내용은 웹앱으로 들어가지 않습니다.
- 자세한 규칙(개발자용): `docs/decision_log.md` 9절.
