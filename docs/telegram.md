# 텔레그램 입찰 공고 보고

나라장터 공고 수집 결과를 텔레그램으로 받아보는 기능입니다. 2026-10-12부터 자동으로 발송됩니다.

---

## 1. 언제, 무엇이 오나

| 언제 (한국시간) | 무엇을 | 조회 기간 | 워크플로 |
|---|---|---|---|
| **평일 09:00** (월~금) | **입찰** 공고 중 아직 안 보낸 공고·[정정] | 직전 3일 게시분 | `report-daily.yml` |
| **매주 월요일 09:10** | **협상 · 규격가격동시입찰 · 사전규격** (텔레그램 + 메일) | 지난 7일 (월~일 게시분) | `report-weekly.yml` |

- 수의계약은 처음부터 뺍니다. 관심·제외 키워드, 최소 예산 필터를 거친 **후보 공고만** 보냅니다.
- **주말엔 매일 보고가 오지 않습니다**(2026-10-19 담당자 요청). 금~일 게시분은 월요일 보고에 함께 담깁니다.
- **정시 발송 (2026-10-20부터, 팀원 수집기 방식)**: 외부 예약 서비스 **cron-job.org**가 평일 09:00에 매일 보고를 깨우고,
  월요일엔 매일 보고가 09:10에 주간 보고를 깨웁니다. GitHub 예약 실행(평일·월 10:10)은 **예비**입니다 —
  GitHub 예약은 몇 시간씩 밀리거나 건너뛰어서(실측 08:00 → 12:21) 하나에만 맡기면 늦습니다. 설정은 아래 "9. cron-job.org".
- **같은 보고가 두 번 오지 않습니다.** 먼저 보낸 실행이 bot-state 브랜치에 "그날(그 주) 보냄"을 남기고, 뒤에 깨운 실행은 수집도
  안 하고 끝납니다(`sent_report_daily.json`·`sent_report_weekly.json`). 매일 보고는 공고마다도 기록해(`sent_bids.json`)
  3일치를 봐도 새 공고·정정공고만 갑니다.
- 새 공고가 없는 날에도 "조건에 맞는 새 공고가 없습니다"를 보냅니다(시스템이 돌았는지 알 수 있게).
- 발송은 회사 PC가 아니라 **GitHub 서버**에서 합니다. PC를 꺼 두어도, 회사망에서 텔레그램 주소가 막혀 있어도 옵니다.
- **수집이 실패하면 담당자 방에는 아무것도 보내지 않고**, 60분 뒤 다시 시도합니다(아래 "실패했을 때").

## 2. 메시지 모양

```
입찰 공고 보고 (10/11 게시분)
후보 3건

1. ○○체험관 전시물 제작설치          ← 누르면 나라장터 공고
   3.2억 · 🔴 D-5 · 자격 충족

2. △△박물관 전시시설 공사
   8.5억 · 🔴 D-9 · 자격 미달(공동수급 가능)

3. □□과학관 체험물 개선
   1.1억 · D-12 · 자격 미확인

지역·공동수급·확인 필요 요건 등 자세한 내용은 첨부 HTML 리포트
[첨부] 공고_입찰_20261012_0800.html
```

| 항목 | 내용 |
|---|---|
| 정렬 | **마감 임박순** (마감 날짜를 모르는 공고는 맨 뒤) |
| 금액 | 1억 이상은 "3.2억", 미만은 "4,500만원" |
| D-N | 카드 마감 기준(입찰참가자격등록 마감 우선)까지 남은 날수. **10일 이내면 굵은 "🔴 D-N"** (텔레그램은 글자 색을 못 바꿔 빨간 점으로) |
| 자격 | 자격 충족 / 자격 미달 / 자격 미확인 — **미달이어도 빼지 않음**. 미달이면 바로 옆에 **(공동수급 가능 / 불허 / 정보 없음)** |
| 본공고 / 사전규격 | 둘 다 있으면 `── 본공고 N건 ──` / `── 사전규격 N건 ──` 구역으로 나눔(번호는 이어서). 본공고 구역 안에서 유형이 섞이면 공고명 앞에 `[협상]` `[규격가격]` `[입찰]` |
| 마감 지난 공고 | 목록에서 빼고 "(마감 지난 N건 제외)"로 건수만 |
| 국방전자조달 공고 | 국방부 등이 국방전자조달(d2b)에 올린 공고는 나라장터에 첨부가 없어 자격을 못 읽음 — 줄 끝에 "· 국방전자조달에서 확인" |
| 경고 | 조회 실패 등이 있으면 제목 아래 `※ …` 줄 |
| 첨부 | 후보가 있을 때만 HTML 리포트(전체 표) — 휴대폰·PC에서 눌러 바로 열림 |
| 이모지 | 쓰지 않음 (마감 임박 🔴만 예외) |

메시지 한 건은 4,096자까지라 후보가 많으면 여러 메시지로 나뉩니다(공고 하나가 중간에 잘리지는 않음).

## 3. 설정 (한 번만)

### 봇 만들기
1. 텔레그램에서 `@BotFather` → `/newbot` → 봇 이름 → 봇 아이디(끝이 `bot`, 예: `jiil_bid_bot`).
2. 받은 **토큰**(`123456789:AA…` 형태, 숫자부터 끝까지 `:` 포함 전체)을 보관. 비밀번호처럼 다룹니다.

### 대화방 ID 알아내기
1. 받을 사람이 봇을 검색해 **`/start`** 를 보냅니다(봇은 먼저 말을 걸 수 없음).
2. 브라우저 주소창에 `https://api.telegram.org/bot토큰/getUpdates` (`<` `>` 없이 `bot` 바로 뒤에 토큰).
3. `"chat":{"id":숫자` 의 숫자가 대화방 ID.
   - `"result":[]` 처럼 비어 있으면 `/start`를 다시 보내고 새로고침.
   - **페이지가 계속 로딩만 되면 회사망에서 텔레그램 주소가 막힌 것** — 휴대폰 LTE로 열거나,
     `@userinfobot`에 `/start`를 보내면 내 ID를 알려줍니다.

### GitHub에 등록
저장소 → Settings → Secrets and variables → Actions → New repository secret
(https://github.com/kdh-007/Negotiate-Contract-Logic-First-try/settings/secrets/actions)

| Name | Secret |
|---|---|
| `TELEGRAM_BOT_TOKEN` | 봇 토큰 |
| `TELEGRAM_CHAT_ID` | 대화방 ID. 여러 곳이면 쉼표로 (예: `111,-100222`) |
| `TELEGRAM_DEV_CHAT_ID` | (선택) **개발자 알림 방** ID — 실패·회복 알림만 여기로 |

앞의 두 값이 없으면 수집은 그대로 하고 **발송만 건너뜁니다.** 개발자 방 ID가 없으면 개발자 알림만 건너뜁니다.

## 4. 팀 단체방에서도 받으려면

1. 단체방을 만들고 봇을 초대합니다.
2. 방에 **`/start@봇아이디`** 를 보냅니다(봇은 단체방의 일반 대화는 읽지 않음).
3. getUpdates 주소를 새로고침 → `"chat":{"id":-100…` (마이너스 포함)이 단체방 ID.
   회사망이면 `@RawDataBot`을 잠깐 초대해 ID를 확인하고 내보내도 됩니다.
4. `TELEGRAM_CHAT_ID`를 `개인ID,-100단체방ID`처럼 쉼표로 이어 다시 저장.

## 5. 손으로 한 번 보내 보기 (시험 발송)

**정기 보고 그대로 미리 보기 (권장)** — 저장소 → Actions → **매일 입찰 보고** 또는 **주간 보고** → Run workflow →
`dry_run` = `true`. 텔레그램·메일은 안 보내고 보낼 메시지를 로그("입찰 공고 수집 · 텔레그램 보고" 단계)에 그대로 찍습니다.
발송 기록도 안 바꿉니다. 실제로 한 번 더 보내려면 `force` = `true`(이미 보낸 날·주말이어도 보냄).

**조건을 바꿔 시험 발송** — 저장소 → Actions → **나라장터 공고 수집** → Run workflow (브랜치 `main`)

| 입력 | 값 |
|---|---|
| `categories` | `입찰` (주간 보고는 `협상,규격가격동시입찰`) |
| `complete_days` | `1` (어제 하루, 주간은 `7`) |
| `telegram` | `true` |
| `pre_spec` | 주간 보고 시험이면 `true` |
| `no_supabase` | `true` (기본값 그대로) |

로그의 "수집 실행" 단계 끝에 `텔레그램 발송: 대화방 1/1곳 성공` 이 찍히면 정상입니다.

**개발자 방 연결만 확인**하려면 `dev_test` 에 `true` 만 넣고 실행합니다(수집은 안 함). 개발자 방에 `[개발자 알림] 시험 메시지입니다 (실제 오류 아님).` 가 오면 정상입니다.

## 6. 실패했을 때 (자동 재시도 · 개발자 알림)

GitHub 서버(미국)에서 나라장터로 가는 접속이 잠깐 끊기는 일이 있습니다. 보통 몇 시간 안에 풀립니다.

| 순서 | 동작 |
|---|---|
| 1 | 접속 한 번마다 최대 5번 곧바로 다시 시도 (잠깐 끊김은 여기서 해결) |
| 2 | 그래도 실패하면 이번 실행은 실패로 끝나고, **60분 뒤** 같은 조건으로 새로 실행 (최대 5번, 약 4시간) |
| 3 | 그 사이 10:10 예비 실행이 먼저 성공하면 그쪽이 보내고, 뒤의 재시도는 발송 기록을 보고 바로 끝남 |
| 4 | 어느 쪽이든 성공하면 담당자 방에 **늦게라도 보고가 그대로 감** — 두 번 가지 않음 |

- **담당자 방에는 실패 알림을 보내지 않습니다.** 담당자가 할 수 있는 일이 없어서입니다.
- **개발자 방**(`TELEGRAM_DEV_CHAT_ID`)에는 이럴 때만 알립니다(`nego/dev_alert.py`, 2026-10-20 팀원 수집기 방식으로 바꿈):
  - **첫 실패:** `[개발자 알림] 매일 입찰 보고 실패` + **원인 한 줄**(나라장터 조회 키 거절 / 나라장터 접속 실패 — 대개 일시적 /
    텔레그램 발송 실패 / 이메일 발송 실패 / 예상하지 못한 오류) + 마지막 오류 몇 줄 + "60분 뒤 다시 시도" + Actions 로그 주소.
  - **5번 모두 실패:** 그날 담당자 보고는 나가지 않았다는 뜻입니다.
  - **재시도 끝에 성공:** `[개발자 알림] 해결됨 — 매일 입찰 보고`.
  - **텔레그램 대화방 일부·전부에 못 보냄:** 실행은 성공으로 끝나 Actions 화면에선 안 보여서 따로 알립니다
    (전부 실패면 기록을 안 남겨 예비 실행이 다시 보냅니다).
  - 가운데 재시도(2~4번째) 실패는 알리지 않습니다(알림이 쌓이지 않게).
- 오류 문구의 나라장터 서비스키는 `serviceKey=***`로 가립니다.
- 재시도 간격·횟수는 각 워크플로 위쪽 `RETRY_DELAY_MINUTES`(60), `MAX_ATTEMPTS`(5). 기다리는 동안 GitHub 러너 시간이 듭니다(실패한 날만).
- 텔레그램 메시지는 3,500자 단위로 나누고, 같은 방에 연달아 보낼 때 **1초 간격**을 둡니다(텔레그램 권장 — 넘으면 429 거절).

## 7. 문제가 생겼을 때

| 증상 | 원인과 해결 |
|---|---|
| 메시지가 안 옴, 로그에 `TELEGRAM_BOT_TOKEN / TELEGRAM_CHAT_ID 없음` | Secrets 이름 오타 — 대소문자·밑줄까지 정확히 |
| 로그에 `chat not found` | 대화방 ID가 틀렸거나, 받을 사람이 봇에 `/start`를 안 보냄 |
| 로그에 `group chat was upgraded to a supergroup chat` 또는 노란 경고 "대화방이 슈퍼그룹으로 바뀌어…" | 방 설정(관리자 지정·이전 대화 공개 등)을 바꾸면 텔레그램이 방 ID를 바꿉니다. 발송은 새 ID로 자동으로 다시 보내지만, 경고에 적힌 **새 ID(-100…)로 Secrets를 바꿔야** 다음부터 바로 갑니다 |
| 로그에 `Unauthorized` | 토큰이 틀림, 또는 `/revoke`로 바꾼 뒤 옛 토큰이 남아 있음 |
| 토큰이 남에게 노출됨 | `@BotFather` → `/revoke` → 봇 선택 → 새 토큰을 Secrets에 다시 저장 |
| 아침에 안 옴 | Actions 탭에서 **매일 입찰 보고** 실행 여부 확인. 09시대 실행이 없으면 cron-job.org 작업의 실행 기록(응답 204가 정상)부터 — 토큰 만료·삭제면 401/404. 그래도 10:10 예비 실행이 보냄 |
| 주말·같은 날 다시 받고 싶음 | **매일 입찰 보고** → Run workflow → `force` = `true` |
| 60일 넘게 저장소 활동이 없음 | GitHub가 예약 실행을 자동으로 멈춤 — 아무 커밋이나 하나 하면 다시 돎 |

발송이 실패해도 수집·리포트는 정상으로 끝납니다(실패로 처리하면 자동 재시도가 같은 보고서를 또 보내기 때문). 대신 Actions 화면에 빨간 오류 표시가 남습니다.

## 9. cron-job.org (정시에 깨우기) 설정 — 한 번만

GitHub 예약 실행 대신 정시에 매일 보고를 깨우는 외부 서비스입니다(무료). 워크플로 파일이 **main에 병합된 뒤에** 설정합니다
(GitHub은 기본 브랜치에 있는 워크플로만 이렇게 깨울 수 있습니다).

**① GitHub 토큰 만들기** — GitHub 오른쪽 위 프로필 → Settings → Developer settings → Personal access tokens →
**Fine-grained tokens** → Generate new token

| 칸 | 값 |
|---|---|
| Token name | `cron-job.org 매일 보고` |
| Expiration | 원하는 기간(최대 1년 — 만료되면 이 표대로 다시 만들어 cron-job.org에 넣기) |
| Repository access | **Only select repositories** → `kdh-007/Negotiate-Contract-Logic-First-try` 하나만 |
| Permissions → Repository permissions | **Actions: Read and write** (나머지는 건드리지 않음) |

만든 토큰(`github_pat_…`)은 그 화면에서 한 번만 보입니다 — 바로 복사해 두세요. 남에게 보이면 안 됩니다.

**② cron-job.org 작업 만들기** — Dashboard → **Create cronjob**

| 칸 | 값 |
|---|---|
| Title | `지일 매일 입찰 보고` |
| URL | `https://api.github.com/repos/kdh-007/Negotiate-Contract-Logic-First-try/actions/workflows/report-daily.yml/dispatches` |
| Execution schedule | Custom → **Days of week: 월~금**, **Hours: 9**, **Minutes: 0** |
| Time zone (Settings 또는 작업 Advanced) | **Asia/Seoul** |
| Advanced → Request method | **POST** |
| Advanced → Headers | `Authorization` = `Bearer github_pat_…(①의 토큰)` · `Accept` = `application/vnd.github+json` · `X-GitHub-Api-Version` = `2022-11-28` · `Content-Type` = `application/json` |
| Advanced → Request body | `{"ref":"main"}` |
| 알림(Notifications) | "실행 실패 시" 메일 켜기 권장 |

저장 후 **Test run**(또는 작업 목록의 ▶)으로 한 번 실행 → 응답 **204**면 정상이고, 몇 초 뒤 GitHub Actions에 **매일 입찰 보고** 실행이
생깁니다. 이미 그날 보냈으면 "이미 보냈습니다 — 건너뜁니다"로 바로 끝나니 시험해도 두 번 가지 않습니다(주말이면 "주말에는…").
주간 보고용 작업은 따로 만들지 않습니다 — 월요일 매일 보고가 깨웁니다.

| 응답 | 뜻 |
|---|---|
| 204 | 정상 |
| 401 | 토큰이 틀렸거나 만료 — ①을 다시 |
| 403 | 토큰 권한에 Actions: Read and write가 없음 |
| 404 | URL 오타, 토큰에 이 저장소가 선택 안 됨, 또는 워크플로가 아직 main에 없음 |
| 422 | body의 `ref`가 틀림(`main`) |
