# 텔레그램 입찰 공고 보고

나라장터 공고 수집 결과를 텔레그램으로 받아보는 기능입니다. 2026-10-12부터 자동으로 발송됩니다.

---

## 1. 언제, 무엇이 오나

| 언제 (한국시간) | 무엇을 | 조회 기간 |
|---|---|---|
| **평일 09:00** | **입찰** 공고 | 어제 하루 (0시~23시59분 게시분). 월요일은 금~일 게시분까지 |
| **매주 월요일 09:10** | **협상 · 규격가격동시입찰 · 사전규격** | 지난 7일 (월~일 게시분) |

- 매일 입찰 보고는 **평일만** 옵니다(2026-10-20 — 팀원 레포 10/19 결정 이식). 3일치를 보고 이미 보낸 공고는 빼서,
  월요일 보고에 금~일 게시분이 함께 들어갑니다.
- 보고에 나간 공고는 사내 웹앱 **판단 기록 탭에 '미판단'으로 쌓입니다** (판단 없이 마감되면 '놓침'). PC가 꺼져 있던 동안의
  보고는 웹앱을 켜면 몇 분 안에 들어옵니다 — `docs/decision_log.md` 8절.
- 수의계약은 처음부터 뺍니다. 관심·제외 키워드, 최소 예산 필터를 거친 **후보 공고만** 보냅니다.
- 조회 기간을 날짜 단위로 딱 잘라서 돌리기 때문에 **같은 공고가 두 번 오거나 빠지지 않습니다.**
- 새 공고가 없는 날에도 "조건에 맞는 새 공고가 없습니다"를 보냅니다(시스템이 돌았는지 알 수 있게).
- 시각은 **외부 예약 서비스(cron-job.org)가 맞춥니다**(2026-10-21부터 — GitHub 예약 실행이 매일 1~3시간 늦게 시작해서).
  GitHub 예약은 12:00 백업으로 남아 있어, 외부 예약이 안 돈 날에만 점심 무렵에 옵니다. 설정은 9절.
- 발송은 회사 PC가 아니라 **GitHub 서버**에서 합니다. PC를 꺼 두어도, 회사망에서 텔레그램 주소가 막혀 있어도 옵니다.
- **수집이 실패하면 담당자 방에는 아무것도 보내지 않고**, 60분 뒤 다시 시도합니다(아래 "실패했을 때").

## 2. 메시지 모양

```
입찰 공고 보고 (10/11 게시분)
후보 3건

1. ○○체험관 전시물 제작설치          ← 누르면 나라장터 공고
   3.2억 · 🔴 D-5 · 자격 충족

2. △△박물관 전시시설 공사
   8.5억 · 🔴 D-9 · 자격 미달(공동수급 가능)

3. □□과학관 체험물 개선
   1.1억 · D-12 · 자격 미확인

지역·공동수급·확인 필요 요건 등 자세한 내용은 첨부 HTML 리포트
[첨부] 공고_입찰_20261012_0800.html
```

| 항목 | 내용 |
|---|---|
| 정렬 | **마감 임박순** (마감 날짜를 모르는 공고는 맨 뒤) |
| 금액 | 1억 이상은 "3.2억", 미만은 "4,500만원" |
| D-N | 카드 마감 기준(입찰참가자격등록 마감 우선)까지 남은 날수. **10일 이내면 굵은 "🔴 D-N"** (텔레그램은 글자 색을 못 바꿔 빨간 점으로) |
| 자격 | 자격 충족 / 자격 미달 / 자격 미확인 — **미달이어도 빼지 않음**. 미달이면 바로 옆에 **(공동수급 가능 / 불허 / 정보 없음)** |
| 본공고 / 사전규격 | 둘 다 있으면 `── 본공고 N건 ──` / `── 사전규격 N건 ──` 구역으로 나눔(번호는 이어서). 본공고 구역 안에서 유형이 섞이면 공고명 앞에 `[협상]` `[규격가격]` `[입찰]` |
| 마감 지난 공고 | 목록에서 빼고 "(마감 지난 N건 제외)"로 건수만 |
| 국방전자조달 공고 | 국방부 등이 국방전자조달(d2b)에 올린 공고는 나라장터에 첨부가 없어 자격을 못 읽음 — 줄 끝에 "· 국방전자조달에서 확인" |
| 경고 | 조회 실패 등이 있으면 제목 아래 `※ …` 줄 |
| 첨부 | 후보가 있을 때만 HTML 리포트(전체 표) — 휴대폰·PC에서 눌러 바로 열림 |
| 이모지 | 쓰지 않음 (마감 임박 🔴만 예외) |

메시지 한 건은 4,096자까지라 후보가 많으면 여러 메시지로 나뉩니다(공고 하나가 중간에 잘리지는 않음).

## 3. 설정 (한 번만)

### 봇 만들기
1. 텔레그램에서 `@BotFather` → `/newbot` → 봇 이름 → 봇 아이디(끝이 `bot`, 예: `jiil_bid_bot`).
2. 받은 **토큰**(`123456789:AA…` 형태, 숫자부터 끝까지 `:` 포함 전체)을 보관. 비밀번호처럼 다룹니다.

### 대화방 ID 알아내기
1. 받을 사람이 봇을 검색해 **`/start`** 를 보냅니다(봇은 먼저 말을 걸 수 없음).
2. 브라우저 주소창에 `https://api.telegram.org/bot토큰/getUpdates` (`<` `>` 없이 `bot` 바로 뒤에 토큰).
3. `"chat":{"id":숫자` 의 숫자가 대화방 ID.
   - `"result":[]` 처럼 비어 있으면 `/start`를 다시 보내고 새로고침.
   - **페이지가 계속 로딩만 되면 회사망에서 텔레그램 주소가 막힌 것** — 휴대폰 LTE로 열거나,
     `@userinfobot`에 `/start`를 보내면 내 ID를 알려줍니다.

### GitHub에 등록
저장소 → Settings → Secrets and variables → Actions → New repository secret
(https://github.com/kdh-007/Negotiate-Contract-Logic-First-try/settings/secrets/actions)

| Name | Secret |
|---|---|
| `TELEGRAM_BOT_TOKEN` | 봇 토큰 |
| `TELEGRAM_CHAT_ID` | 대화방 ID. 여러 곳이면 쉼표로 (예: `111,-100222`) |
| `TELEGRAM_DEV_CHAT_ID` | (선택) **개발자 알림 방** ID — 실패·회복 알림만 여기로 |

앞의 두 값이 없으면 수집은 그대로 하고 **발송만 건너뜁니다.** 개발자 방 ID가 없으면 개발자 알림만 건너뜁니다.

**피드백 구글 시트**(선택, 2026-10-20) — 매일·주간 보고에 나간 공고를 구글 시트에 한 줄씩 쌓습니다(공고번호가 이미 있으면 건너뜀).
사무실 밖에서 보는 용도이고, 판단은 웹앱 판단 기록에서 합니다. 없으면 시트만 건너뜁니다.

| Name | Secret |
|---|---|
| `GOOGLE_SERVICE_ACCOUNT_JSON` | 구글 서비스 계정 키 JSON 파일 내용 전체. 시트를 이 계정 이메일(`client_email`)에 **편집자**로 공유해야 함 |
| `FEEDBACK_SHEET_ID` | 시트 주소 `…/spreadsheets/d/` 와 `/edit` 사이 |

탭 이름은 `피드백`(환경변수 `FEEDBACK_SHEET_NAME`으로 바꿀 수 있지만 워크플로에는 연결하지 않음).
시스템은 A~R열(18개)만 쓰고 S~V열(판정·오판사유·판정자·판정일)은 비워 둡니다. 기록이 실패해도 보고는 이미 나간 뒤라
실행은 성공으로 끝나고 Actions 로그에 빨간 오류(`피드백 시트 기록 실패`)만 남습니다 — 403이면 시트 공유를 확인하세요.

## 4. 팀 단체방에서도 받으려면

1. 단체방을 만들고 봇을 초대합니다.
2. 방에 **`/start@봇아이디`** 를 보냅니다(봇은 단체방의 일반 대화는 읽지 않음).
3. getUpdates 주소를 새로고침 → `"chat":{"id":-100…` (마이너스 포함)이 단체방 ID.
   회사망이면 `@RawDataBot`을 잠깐 초대해 ID를 확인하고 내보내도 됩니다.
4. `TELEGRAM_CHAT_ID`를 `개인ID,-100단체방ID`처럼 쉼표로 이어 다시 저장.

## 5. 손으로 한 번 보내 보기 (시험 발송)

저장소 → Actions → **나라장터 공고 수집** → Run workflow (브랜치 `main`)

| 입력 | 값 |
|---|---|
| `categories` | `입찰` (주간 보고는 `협상,규격가격동시입찰`) |
| `complete_days` | `1` (어제 하루, 주간은 `7`) |
| `telegram` | `true` |
| `pre_spec` | 주간 보고 시험이면 `true` |
| `no_supabase` | `true` (기본값 그대로) |

로그의 "수집 실행" 단계 끝에 `텔레그램 발송: 대화방 1/1곳 성공` 이 찍히면 정상입니다.

**개발자 방 연결만 확인**하려면 `dev_test` 에 `true` 만 넣고 실행합니다(수집은 안 함). 개발자 방에 `[개발자 알림] 시험 메시지입니다 (실제 오류 아님).` 가 오면 정상입니다.

## 6. 실패했을 때 (자동 재시도 · 개발자 알림)

GitHub 서버(미국)에서 나라장터로 가는 접속이 잠깐 끊기는 일이 있습니다. 보통 몇 시간 안에 풀립니다.

| 순서 | 동작 |
|---|---|
| 1 | 접속 한 번마다 최대 5번 곧바로 다시 시도 (잠깐 끊김은 여기서 해결) |
| 2 | 그래도 실패하면 이번 실행은 실패로 끝나고, **60분 뒤** 같은 조건으로 새로 실행 |
| 3 | 최대 5번 실행(첫 시도 포함, 약 4시간). 매일 보고면 08시 → 09 → 10 → 11 → 12시 |
| 4 | 중간에 성공하면 담당자 방에 **늦게라도 보고가 그대로 감** (조회 기간이 날짜 단위라 내용 같음) |

- **담당자 방에는 실패 알림을 보내지 않습니다.** 담당자가 할 수 있는 일이 없어서입니다.
- **개발자 방**(`TELEGRAM_DEV_CHAT_ID`)에는 두 경우에만 알립니다.
  - **5번 모두 실패:** `[개발자 알림] 나라장터 수집 실패 — 5회 모두 실패` + 유형·기간, 마지막 오류 몇 줄, Actions 로그 주소.
    그날 담당자 보고는 나가지 않았다는 뜻입니다.
  - **재시도 끝에 성공:** `[개발자 알림] 나라장터 수집 회복 — 3번째 시도에서 성공` (서버 문제가 있었다는 기록용)
- 오류 문구의 나라장터 서비스키는 `serviceKey=***`로 가립니다.
- 재시도 간격·횟수는 `daily.yml` 위쪽 `RETRY_DELAY_MINUTES`(60), `MAX_ATTEMPTS`(5). 기다리는 동안 GitHub 러너 시간이 듭니다(실패한 날만).

## 7. 문제가 생겼을 때

| 증상 | 원인과 해결 |
|---|---|
| 메시지가 안 옴, 로그에 `TELEGRAM_BOT_TOKEN / TELEGRAM_CHAT_ID 없음` | Secrets 이름 오타 — 대소문자·밑줄까지 정확히 |
| 로그에 `chat not found` | 대화방 ID가 틀렸거나, 받을 사람이 봇에 `/start`를 안 보냄 |
| 로그에 `group chat was upgraded to a supergroup chat` 또는 노란 경고 "대화방이 슈퍼그룹으로 바뀌어…" | 방 설정(관리자 지정·이전 대화 공개 등)을 바꾸면 텔레그램이 방 ID를 바꿉니다. 발송은 새 ID로 자동으로 다시 보내지만, 경고에 적힌 **새 ID(-100…)로 Secrets를 바꿔야** 다음부터 바로 갑니다 |
| 로그에 `Unauthorized` | 토큰이 틀림, 또는 `/revoke`로 바꾼 뒤 옛 토큰이 남아 있음 |
| 토큰이 남에게 노출됨 | `@BotFather` → `/revoke` → 봇 선택 → 새 토큰을 Secrets에 다시 저장 |
| 아침에 안 옴 (점심 무렵에 옴) | 외부 예약이 안 돌아서 12:00 백업이 보낸 것. cron-job.org 실행 기록에서 응답 확인 — `401`이면 토큰 만료·오타(9절에서 새로 만들어 바꿈), `422`면 본문(입력값) 오타 |
| 하루 종일 안 옴 | Actions 탭에 그날 실행이 있는지 확인. 백업 예약도 GitHub가 늦게 시작할 수 있음 |
| 60일 넘게 저장소 활동이 없음 | GitHub가 **백업** 예약 실행을 자동으로 멈춤(외부 예약은 그대로 돎) — 아무 커밋이나 하나 하면 다시 돎 |

발송이 실패해도 수집·리포트는 정상으로 끝납니다(실패로 처리하면 자동 재시도가 같은 보고서를 또 보내기 때문). 대신 Actions 화면에 빨간 오류 표시가 남습니다.

## 9. 정시 발송 — 외부 예약 서비스 (2026-10-21, 사용자 결정)

GitHub 예약 실행은 붐비는 정시(09:00)에 1~3시간씩 늦게 시작했습니다(10/16~10/20 실측 10:57~11:28). 그래서 **cron-job.org**(무료)가
정해진 시각에 GitHub "Run workflow" 버튼을 대신 누르게 했습니다(`workflow_dispatch` API — 보통 1분 안에 시작).

- 같은 날 같은 모드의 실행이 이미 있으면(진행 중·성공) **12:00 백업 예약은 수집 없이 끝납니다** — 두 번 오지 않습니다.
  Run 이름("수동 실행 · 입찰 · 직전 3일 · 사전규격 false · 텔레그램 true")으로 확인하므로 **아래 본문 값을 바꾸면 안 됩니다.**
- 수집이 실패하면 예전처럼 60분 뒤 재시도합니다(재시도 Run도 같은 이름).

### ① GitHub 토큰 만들기 (저장소 관리자)

1. GitHub 오른쪽 위 프로필 → **Settings** → 왼쪽 맨 아래 **Developer settings** → **Personal access tokens** → **Fine-grained tokens** → **Generate new token**
2. Token name `cron-job.org 정시 발송`, Expiration **최대(1년)** — 만료일을 달력에 적어 둘 것
3. Resource owner **jiil-bid-monitor**, Repository access **Only select repositories** → `Negotiate-Contract-Logic-First-try`
4. Permissions → Repository permissions → **Actions: Read and write** (나머지는 그대로)
5. Generate → `github_pat_…` 토큰을 복사(이 화면을 벗어나면 다시 못 봄). 조직 설정에 따라 조직 관리자 승인이 필요할 수 있음

**지금 토큰은 팀원 계정 `iamhiki`로 만들었습니다**(2026-10-21, 만료 2027-10-21 무렵). 그 계정에 이 저장소 쓰기 권한이 있어야 하고(없으면 `403`),

### ② cron-job.org 예약 두 개 만들기

https://console.cron-job.org 가입 → **Create cronjob**. 두 개 모두 공통:

| 항목 | 값 |
