## 2. 클라우드 서버로 옮기기 준비 (브랜치 `claude/cloud-server`)

계기: "내 PC가 꺼진 이후에도 팀원들이 서버를 이용하게". 어떤 방법이든 웹앱이 도는 컴퓨터는 늘 켜져 있어야 한다는 점을 설명하고
① 사내 상시 PC ② 클라우드 ③ 이 PC 계속 켜 두기를 비교 → **사용자: 클라우드, 네이버클라우드**(원화 결제·한국어, Micro 1년 무료).

| 만든 것 | 하는 일 |
|---|---|
| `deploy/upload_from_pc.sh` | 서버 PC Git Bash에서 한 줄. 판단 기록(`data/`)·과거 실적 폴더·구글 키·인증키를 묶어 올리고 서버 설치 실행. PC 웹앱이 켜져 있으면 멈춤 |
| `deploy/setup_server.sh` | 우분투 서버 설치 — 파이썬·웹앱·Caddy(https, `<IP>.sslip.io` 무료 인증서)·systemd 자동 실행·새 무작위 토큰. 다시 돌려도 판단 기록·토큰 유지 |
| `deploy/update_server.sh` | 코드 업데이트(예전 `Ctrl+C → git pull → start.sh` 대신) |
| `deploy/backup_from_server.sh` | 서버 판단 기록 백업을 PC 구글 드라이브 폴더로 받아 오기(주 1회쯤) |
| `webapp/server.py` | `COOKIE_SECURE=1`이면 토큰 쿠키에 `Secure` |
| `docs/cloud_server_setup.md` | 네이버클라우드 가입 → VPC·서브넷 → Micro 서버 → ACG(22는 사무실 IP만, 80·443) → 옮기기 → 업데이트·백업·문제 해결 |

- 인터넷에 열리므로 http + `jiil2026` 토큰은 그대로 쓰면 안 됨 → https만, 토큰은 서버에서 새로 만든 32자 무작위 값.
- 검증: 이 환경에서 `setup_server.sh`를 systemctl·apt만 가짜로 두고 실제로 돌림 — 설치, PC 묶음 풀기, 웹앱 켜짐, bot-state 보고 8건 합치기,
  토큰 없는 요청 401, 다시 돌렸을 때 .env·판단 기록 유지. `upload_from_pc.sh`는 scp·ssh를 가짜로 두고 묶음 내용(.git 제외) 확인.
  처음 돌렸을 때 tar가 자기 자신(묶음 파일)을 읽어 "file changed" 오류로 멈춘 것을 고침.
- 실측 미확인: 네이버클라우드 실제 서버(메뉴 이름은 기억 기준), Let's Encrypt 인증서 발급, 서버에서 나라장터 호출·시트 쓰기.
- 테스트: 전체 557개 통과(새 테스트 1개 — Secure 쿠키).
