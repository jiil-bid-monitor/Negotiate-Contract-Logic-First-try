## 1. 키워드 오탐 — 형태소 분석기 + 문맥 모델 (jiil #3, 이 레포 #207)

계기: 최근 7일 본공고 14건의 싱크로율 근거를 사용자가 하나씩 보며 확인 — 낱말 속 글자 오탐(계약서가→서가, 전시공간→시공,
중심의→심의, 체험관련→체험관)과 행정 줄 근거("홈페이지주소 | E-mail").

- **형태소 경계(Kiwi)**: 키워드가 낱말 경계에 맞을 때만 근거. 한 형태소 안(국립민속박물관의 '박물관')은 인정, 사용자 사전(사인물·물놀이터 등).
- **줄 분류기(문맥 모델)**: 행정 줄을 거름 — 이름표 3,000줄(Claude가 붙이고 사용자가 50줄 확인), 글자 조각 TF-IDF + 로지스틱 회귀, 교차검증 91.5%.
- **부정 표현**: 키워드 뒤 "~가 아닌·제외·별도 발주"면 제외(사용자 결정: "단순 놀이터가 아닌" 같은 비교 문장도 뺌).
- **잡음 줄**: 한글 없는 긴 영문·숫자 줄(파일 ID) 제외, 같은 문서가 두 번 실린 같은 줄은 한 번만, 근거 줄은 키워드 앞뒤로 잘라 보임.
- **새 키워드** 설비·장비/"미디어 시스템"(사용자 지정 이름).
- **점수**: 시설·주제 무게 1.6 → 1.0, 등장 횟수 무게 최대 2배(사용자 결정 — 주제보다 과업이 같은 사업을 높게).
- **기준선**: 높음 0.65 그대로, 경계선 0.45 → **0.55**(14건 기준 임시 — 참가·불참 기록 30건쯤 쌓이면 다시).
- 새 패키지 kiwipiepy·scikit-learn(requirements). 없으면 싱크로율만 "판정 불가".
- 팀원 승인 받고 반영(사용자: "모델 사용은 허용 받았어").

## 5. 키워드 학습 자동화 — 예외 낱말 후보를 매주 개발자 방으로 (jiil #7, 이 레포 #215)

사용자 질문 "규칙을 계속 찾는 방향밖에 없나" → 세 방식(지금 규칙 / 키워드 학습 자동화 / 투찰 이력 공고명 분류) 비교 후 **키워드 학습 자동화 먼저**.

- `evaluation/exclusion_suggest.py`(jiil): 키워드가 더 긴 낱말 속에 잡힌 곳을 모아 오탐 가능성 순. '단독' = 그 낱말만으로 칸이 생긴 공고 수.
  **규칙은 안 바꿈** — 사람이 승인한 낱말만 넣는다.
- 순위는 판단 기록(`evaluation/exclusion_feedback.json`)으로 학습 — 로지스틱 회귀(키워드 앞뒤 글자 조각, 기관·법령 꼴, 고유명사, 형태소 경계,
  지일 과거 문서에 나온 낱말인지). 첫 기록 525건(Claude가 붙임 — 상위 300 + 무작위 200. 상위만 붙이면 평범한 합성어가 학습에 없어 과대평가됨).
- 검증: 교차검증 AUC 0.87(손 규칙 0.70), 상위 20개 중 오탐 20개. 그날 손으로 찾은 오탐을 숨기고 돌리면 기관·법령·부서 꼴은 상위에서 다시 찾지만,
  뜻을 알아야 하는 것(감사인·편집기·현실감)은 못 찾음 → 사람 검토는 계속 필요.
- 사용자 결정: **법령 이름 속 키워드(소방법·문화재보호법)는 오탐**, 보고서는 **웹앱이 아니라 개발자 방 텔레그램**(웹앱은 담당자가 봐서).
- `nego/exclusion_report.py` + `daily.yml` 단계: 주간 보고(월요일, 협상·규격가격·사전규격) 성공 뒤 개발자 방에 상위 10개 + HTML 첨부.
  실패해도 수집·담당자 보고엔 영향 없음. Actions엔 과거 문서 원문이 없어 `evaluation/past_words.json`(키워드 든 낱말 7,078개)을 묶음에 넣음.
