## 1. 투찰내역 화면 (사용자 요청, 모두 main 병합)

- 개찰 전 줄: 투찰 마감('마감' + 시각)과 개찰 일시를 붉게, 굵기는 보통.
- 개찰이 끝난 줄: 결과 안에 **투찰 업체 목록**(21라인 경쟁업체 표 모양, 좌우 넘김 없음) — 추첨번호·대표자 열은 뺌(대표자는 API 값이 비어 '-').
  낙찰하한선 미달 업체는 '-N등'(금액 큰 순).
- 표 정리: 공고번호·발주처 줄 나눔, 하한율 줄 나눔, 기준 사정률만, 개찰 결과엔 개찰 시각만, 낙찰 결과가 나오면 '낙찰'/'탈락',
  실제 사정률 칸은 지일 등수·하한선 통과/미달 먼저(실제 사정률은 부가 정보), 지일 등수 칸은 등수만(탈락 사유 중복 표기 없앰).
- 개찰은 투찰 마감과 같은 시각에 진행(결과 공개까지 걸리는 시간은 공식 규정 없음 — 사용자에게 설명).

## 2. 정량평가서 (경남교육청 학생안전체험원 R26BK01809838 제보 등, 모두 main 병합)

- 과거 제안요청서 검사 남은 3건 규칙 → 빈 칸 0개.
- 서식 목록 '번호 | 서식명' 표 읽기, '【별지서식 N】' 머리 자르기.
- 통합서식 빈 값: 생년월일·공고번호·신청인(대표자)·위임장·서약서·홈페이지·메일·연혁(답안 칸 안으로)·실적증명서 신청인 줄·신용평가등급(PDF 확인서 → 등급 칸 아래 칸).

- 자기평점: 표 '배점(점)' 머리 모양, 기술인력 '등급별 계수 × 인원 합 → 점수 구간'(경남교육청), 구간 줄마다 평점 칸이 따로인 표.
- **오류가 반복되는 근본 원인**(사용자 질문): 규칙은 본 모양만 알고, 과거 표본이 좁고, 예전 검사는 빈 칸만 셌고, 실패가 조용함 →
  사용자 결정 1·2번 진행(3번 AI 대체 읽기는 보류 — API 키 사용 단점(회사 자료 외부 전송·비용·결과 흔들림)도 설명함):
  - ① `quantdocs/health.py` — 서식 빠짐·목록 못 읽음·배점기준 못 읽음·평가표 못 읽음·기준 없음·빈 칸·모르는 이름표까지 셈.
    `scripts/quant_fill_check.py`는 사업 폴더 단위. 158개 사업: 배점기준 못 읽음 45 · 서식 빠짐 27 · 목록 못 읽음 11 · 평가표 못 읽음 8 ·
