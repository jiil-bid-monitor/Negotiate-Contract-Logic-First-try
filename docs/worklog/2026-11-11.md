# 2026-11-11 작업 정리

자세한 결정·규칙은 `CLAUDE.md`, 인수인계는 `docs/HANDOFF.md`. 회사 자료·지일 투찰 이력은 저장소에 올리지 않음.

## 1. 나라장터 조회기간 한도 7일 대응 (main 병합)

- 웹앱 '최근 7일' 수집이 "입력범위값 초과"로 실패 — 공공데이터포털 공지(11/10): 입찰공고정보서비스 조회기간 **1개월 → 7일**.
- '최근 N일' = **오늘 포함 N일, 00시부터**(사용자 요청). 14·30일·직접 지정은 7일씩 나눠 받아 합침(30일 = 5번 × 조회 8종).
- 30일 수집 예상 시간은 그대로 약 1시간 10~20분(대부분 첨부 읽기).

## 2. 정량평가서 서식 채우기 (main 병합)

- 서명 줄 '(인)'이 다음 줄로 넘어가던 것 — 이름 너비만큼 빈칸을 뺌.
- '서 약 자 : 업체 대표     (인)'처럼 '대표'가 미리 적힌 줄에 대표 성명.
- 실적 표 사업명 글꼴이 줄마다 다르던 것 — 열 머리 글꼴로.
- **채운 값은 늘 휴먼명조 보통 굵기**(사용자 결정). 발주처가 미리 적은 글(제출처 등)은 그대로.
- 연혁 칸: 왼쪽 정렬 + 둘째 줄은 날짜 뒤 내용 시작에 맞춤.
- 화면 기술인력·특허 체크 목록은 처음엔 모두 해제. 0명을 고르면 최저 구간 점수(예: 30점 미만 2.0).
- 기술인력 '각 0.5점' 표를 못 읽던 것, 등급 줄마다 평점 칸이 있는 서식(특급 1 · 고급 0.4 · 중급 0 · 초급 0.2)으로 나눠 채움.
- 준비표 엑셀이 서류 이름 속 제어 문자로 멈추던 것('cannot be used in worksheets') 고침.
- 새 공고 미리 검사·개발자 방 알림은 **삭제**(사용자 결정 — 필요 없음).

## 4. Claude로 서식 읽기 시험 (브랜치 `claude/quant-ai-pilot`, 병합 전)

- 규칙·표본을 늘려도 새 서식 모양마다 틀림 → **규칙 먼저, 검사가 못 읽었다고 판정한 곳만 Claude에게**(배점기준·모르는 이름표).
- 사용자 결정: **서버 PC의 Claude Code(Max 구독) `claude -p`**로 — 토큰 요금 없음, Max 사용량을 같이 씀. 회사 자료는 안 보냄(공개 공고 글·이름표만).
- 시험 스크립트 `scripts/quant_ai_check.py`(과거 표본으로 '규칙만 → Claude 기준' 문제 수 비교). 웹앱은 아직 안 바꿈.
- 서버 PC Claude Code 설치·PATH 등록·로그인 완료. 점검(--dry-run): 158사업 중 배점기준을 물을 곳 45·이름표 91.
- 배점기준 사업 3개 시험: **배점기준 못 읽음 3 → 0**, 실적 구간·신인도는 원문 구조대로 읽음. 경영상태는 점수 계산 형식(종류별 등급 줄)으로 받게 고침.
- 처음엔 제안요청서를 6만 자까지 보내 Max 사용량이 커서 멈춤 → **정량평가 부분 1만 2천 자만** 보내게 고침(3사업 78,506 → 약 36,000자, 결과 같음).
- **사용자 결정: 사용량이 커서 시험은 다음에.** 평가표 못 읽음 0 → 2(기준이 생겨 드러난 자기평가표 서식 문제)는 규칙 숙제.
